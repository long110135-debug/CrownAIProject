### 二、handicap方向逻辑审计：确认是 let球方机械映射

**确认：当前 `_determine_direction` 就是过度简化映射，不得称为方向修复完成。**

代码证据（handicap_model.py L172-205）优先级：
1. 升盘 → home
2. 降盘 → away
3. 盘口不变 → `line_favorite(handicap)`：主让→home / 客让→away / 平手→neutral
4. 平手 → 比水位

**关键缺陷**：`change_score`和`water_score`作为参数传入但函数体内**从未使用**。盘口不变时方向仅由让球身份决定，完全不看水位高低/水位变化/盘口深浅/市场异常。market_model无诱热时同样只返回`line_favorite`（heat_side），诱热阈值40过高几乎不触发。

**三场固定样本完整决策过程**（水位已decimal→HK转换）：

| 项目 | Hearts | Shamrock | Banfield |
|------|--------|----------|----------|
| handicap(主队视角) | -0.25 | -0.25 | -0.25 |
| 让球方 | 客(Sturm) | 客(Ararat) | 客(Sarmiento) |
| 受让方 | 主(Hearts) | 主(Shamrock) | 主(Banfield) |
| 开盘线/当前线 | 客让0.25/客让0.25 | 客让0.25/客让0.25 | 客让0.25/客让0.25 |
| 盘口加深/减弱 | 不变 | 不变(水位异动) | 不变 |
| 让球方价格(客HK水) | 1.30(极高) | 0.90 | 1.08(>1.0) |
| 受让方价格(主HK水) | 0.32 | 0.35 | 0.30 |
| 市场异常 | trap_risk25<40无 | 无 | trap_risk25<40无 |
| handicap方向 | **away** | **away** | **away** |
| market方向 | **away** | **away** | **away** |

**三场全部机械输出away，仅因都是客让0.25。** 水位差异巨大（客水1.30/0.90/1.08）但对方向零影响。

**假想场景验证缺陷**：客让0.25，让球方极低水0.70（强信心）vs 极高水1.15（诱热）——当前逻辑两者都输出away。合理模型应对前者强化away、后者警惕反转home/neutral。

**修复设计（仅设计，未实现，未调权重）**：让球方身份作为先验起点而非结论，方向由多信号加权合成：
- Step1 基线方向+强度（盘口越深先验越强）
- Step2 让球方水位位置信号（<0.80强支持 / >1.00诱热警告，按让球方身份动态取价）
- Step3 水位动态信号（开盘→当前让球方水位升降）
- Step4 盘口变动信号（升盘/降盘，权重最高）
- Step5 市场异常（诱热成立则反转）
- Step6 实力交叉验证（信心乘数）
- 合成：`final_score = Σ(信号×强度×权重)×交叉因子`，超阈值输出让球方/受让方/neutral。权重 W_line > W_trap > W_dynamic > W_water > W_base。

### 四、时间存储格式审计

**确认：全部17个时间字段均为naive字符串，不满足"timezone-aware UTC或带+08:00 ISO 8601"标准。**

| 字段 | 格式 | 达标 |
|------|------|:---:|
| matches.match_time | naive北京时间 `2026-07-30 06:30` | ✗ |
| prediction_history.kickoff | naive北京时间（含旧中文格式`08月21日 15:00`） | ✗ |
| odds_timeline.record_time | naive本地 `datetime.now()` | ✗ |
| closing_odds.closing_time | naive本地 | ✗ |
| predicted_at / settled_at / prematch_at | naive本地 | ✗ |
| recommendation_experiments各时间 | naive本地 | ✗ |
| match_result.settled_at | naive本地 | ✗ |
| performance_log/filter_funnel.log_date | naive日期 | ✗ |

无任何字段含`+08:00`/`Z`/时区标记。系统依赖隐含假设：所有时间同为naive北京时间+系统运行UTC+8。代码无timezone/pytz/zoneinfo。

**6个时间比较点**（lock_closing_odds、analyze_matches、prematch_analyze、track的LIKE查询、save_closing_odds防覆盖、settle的_match_date）全部依赖此假设。改为timezone-aware需同步修改这6处，否则TypeError或逻辑错误。**此项为阻断项，需架构决策后再改。**

### 五、统一亚盘结算函数（已实现）

**唯一函数 `settle_asian_handicap(direction, handicap_str, home_score, away_score)`**（utils/odds_math.py）：
- 返回 win/half_win/push/half_loss/loss/invalid/no_bet
- 覆盖盘口 0, ±0.25, ±0.5, ±0.75, ±1, ±1.25, ±1.5, ±2
- 逻辑：margin=(home-away)-hdp（hdp主让正/客让负）→ 主队视角结果 → 按推荐方向映射（away翻转）
- 配套`hit_to_pnl`（win+1/half_win+0.5/push0/half_loss-0.5/loss-1/no_bet&invalid=None）

**调用统一**：legacy、consensus（_settle_shadow_experiment）、普通推荐（auto_settle）、报表PnL全部调用此函数。删除旧`_direction_to_hit`/`_hit_to_pnl`。prediction_history新增hit_result列存详细结果，整数hit向后兼容（win/half_win→1, loss/half_loss→0, push/no_bet/invalid→2）。

**8个固定用例全部通过**：主让1.5/1:0/home→loss、主让1/1:0/home→push、主让0.75/1:0/home→half_win、主让0.25/0:0/home→half_loss、主受让0.25/0:0/home→half_win、客让0.25/平局/away→half_loss、客让0.75/客胜1球/away→half_win、客让1/客胜1球/away→push。

**历史结算dry-run（不覆盖）**：
- 普通推荐13场，2处差异：Banfield/San Lorenzo的draw从hit=0(误判未中)→修正为invalid(hit=2)。这是正确修正（draw非亚盘合法方向）。
