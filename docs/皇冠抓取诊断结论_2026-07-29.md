# 皇冠球探网抓取诊断结论 (2026-07-29)

## 问题
crown_daemon 持续报"无目标联赛"，皇冠中文队名+盘口无法入库，导致小联赛球队显示API-Football英文名。

## 根因（已确认）

1. **联赛列表异步渲染不稳定**：皇冠SPA（hga050.com）的联赛列表（`id=league_数字` 元素，如 `league_100021`=英格兰超级联赛）由前端JS异步渲染，加载时机非确定性。旧daemon导航后仅 `time.sleep(8)` 固定等待即提取，常常提取过早导致空列表。

2. **登录与SPA框架正常**：登录成功、`parentClass.dispatchEvent` 可用、`top.userData.uid`/`top.ver` 可提取。问题不在登录，在联赛数据的异步加载时机。

3. **站点限流/不稳定**：连续多次Playwright访问会触发SPA加载超时，诊断期间多次复现。

## 关键API发现（供后续实现稳定抓取）

皇冠所有数据经 `POST https://hga050.com/transform.php?ver=<token>` 获取，`ver` 为会话版本token。

**已捕获的数据接口：**

| 调用 | 返回 | 说明 |
|------|------|------|
| `p=league_index&gtype=ft&showtype=early/today&langx=zh-cn&uid=<uid>&ts=<ms>&rtype=r` | 76011字符HTML壳 | 联赛列表页骨架，联赛数据由JS二次加载渲染 |
| (联赛数据调用) | `<code>get_league_list_All</code>` XML, 13571字符 | **真正的联赛列表数据**，含中文联赛名+日期列表 |
| (比赛数据调用) | `<code>601</code>` XML | 含各级别比赛计数(FU_count=405等) |
| `p=sendIovation` | XML | iovation反爬黑盒上报 |

**请求参数样本（league_index）：**
```
POST transform.php?ver=b399d74cd419dc30e97059c9e4069005_1784785429837
content-type: application/x-www-form-urlencoded
body: p=league_index&ver=<ver>&langx=zh-cn&uid=<uid>&ts=<毫秒时间戳>&gtype=ft&showtype=early&rtype=r
```
- `uid` 来自登录后 `top.userData.uid`
- `ver` 来自 `top.ver`
- `langx=zh-cn` → 返回中文队名/联赛名

## 本轮已实施改进

`crown_daemon.py` `_fetch_odds()`：将固定 `time.sleep(8)` 改为**导航+轮询等待+3次重试**（每次导航后轮询最多20秒等待 `league_数字` 元素出现）。比固定等待更可靠，但无法根治SPA渲染的非确定性。

## 后续建议（稳定抓取方案）

**推荐方向：直接调用 transform.php 数据接口，绕过DOM渲染。**

1. 登录后用 `page.request.post()`（共享浏览器session/cookie）直接调 transform.php
2. 需补全 `get_league_list_All` 与比赛数据接口的确切请求参数（本轮因站点限流未能稳定复现触发请求）
3. 解析返回的XML拿中文联赛名+队名+盘口，完全不依赖flaky的DOM渲染
4. 注意处理 iovation 反爬 token 与会话续期

**前置条件**：在站点非限流状态下捕获 `get_league_list_All` 的完整请求（method/headers/postData），建议间隔较长时间单次抓取以避免触发限流。

## 架构提醒

即使皇冠抓取完全修复，`sync_today`（API-Football源，英文名）与皇冠（中文名）产生的是**两套独立match_id**，不会自动合并。要真正"以皇冠为准"，需二选一：
- (A) sync数据源整体切换为皇冠
- (B) 建立 皇冠中文名 ↔ API-Football英文名 动态映射表，sync时优先查皇冠名

此为后续架构决策，本轮未实施。
